## 安装与启动

在 Windows PowerShell、项目根目录 `E:\A-codehub\vision_learning` 执行以下命令，为当前 Python 环境安装 OBS 可选客户端。需要联网下载，通常不需要管理员权限；不会启动摄像头。本次已安装 `obsws-python 1.8.0`。

```powershell
python -m pip install -r requirements-obs.txt
```

以下命令只验证客户端能导入，不连接 OBS、不取画面：

```powershell
python -c "import obsws_python; print('OBS client available')"
```

在同一项目目录执行以下命令启动网页服务并自动打开浏览器；不需要管理员权限，不会自动连接相机。若旧版本服务已在运行，应在原终端停止旧服务再启动，因为启动脚本会复用已有服务。

```powershell
python scripts/camera_web.py
```

1. 在 OBS 的“工具 → WebSocket 服务器设置”启用服务器并保留密码认证。
2. 后端连接固定为本机 `127.0.0.1`，读取当前 Windows 用户的 `%APPDATA%/obs-studio/plugin_config/obs-websocket/config.json`，不修改该文件。密码不进网页、项目 YAML 或浏览器存储。
3. 如采用便携版或独立连接参数，可在启动后端的进程环境中设置 `OBS_WEBSOCKET_PORT`、`OBS_WEBSOCKET_PASSWORD`；环境变量优先。不要将密码提交到仓库或发送给前端。
4. 关闭独立 DroidCam Client，在 OBS 中确认手机源能正常出画面。
5. 在网页“相机来源”选择“OBS DroidCam”，点击“刷新 OBS 来源”，选择手机输入源，再点击“连接 OBS”。连接时会准备只含该手机源的专用场景。
6. 连接后，现有“实时画面”区域显示实时取景预览；使用“手动拍照”“开始自动拍照”和“开始录像”按钮。自动拍照会持续执行，直到再次点击停止。
7. 照片目录、自动拍照间隔和本次录像目录均可在网页输出设置中修改。录像格式、尺寸和帧率沿用 OBS 设置。
8. 桌面音频和全局麦克风必须静音，避免手机录像混入电脑声音；`DroidCam OBS` 自身的音频不受该检查限制，可按需要开启或静音。

## 手机画面范围

OBS 的 `StartRecord` 控制节目输出，并不接受输入源参数。因此本项目使用只引用选定 DroidCam 输入的手机专用场景；不删除或隐藏原场景中的桌面源。连接时会优先复用已有且内容安全的 `手机采集-*` 场景；只有找不到可复用场景时才按来源生成固定名称，避免每次服务重启都新增一个随机场景。新场景使用直接切换转场，画面等比例适配 OBS 画布，不裁切，比例不同时保留黑边。协议依据：[OBS 官方请求文档](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md#startrecord)。

开始录像前，后端检查输入类型、专用场景中只能有一个启用的所选手机源、当前节目场景一致、没有场景滤镜或进行中的转场，并检查桌面音频和全局麦克风已静音。`DroidCam OBS` 来源自己的音频可以保留。正在录像或直播时不允许准备或切换手机源。输入源本身的 DroidCam 参数和滤镜沿用 OBS 设置。

录像期间后端约每 0.5 秒检查场景及全局音频，发现不符合要求时停止本项目录像并报错。**OBS 是独立进程，其他客户端或用户仍可修改它；检测到停止之间可能已经录入被修改的画面。录像时不要在 OBS 或其他控制端切换场景、改动来源或音频。此控制方式不提供逐帧隔离保证。**

录像格式、分辨率和帧率沿用 OBS 配置。网页填写的录像目录会在开始录像前创建并临时写入 OBS，停止后显示 OBS 返回的文件路径并恢复原 OBS 目录。OBS 渲染 FPS 不代表手机真实独立帧率；本页面不把两者等同。

截图直接调用 `SaveSourceScreenshot`，目标是手机输入源，格式为 PNG，省略缩放参数以保留输入源分辨率。后端检查文件存在、PNG 格式和尺寸，文件名包含时间和随机标识。协议依据：[OBS 官方截图文档](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md#savesourcescreenshot)。

自动拍照在开始后尽快拍第一张，随后按间隔持续执行，直到用户点击停止。间隔允许 0.2～86400 秒。磁盘或 OBS 太慢时会跳过已经错过的时点，不突发补拍。相对目录以项目根目录为基准。

## 预览、日志与生命周期

- OBS 预览直接读取选定的 DroidCam 输入源，不读取节目画面，因此不会混入桌面采集层。浏览器在上一张 JPEG 完成显示后立即请求下一张，不设置固定帧间等待，也不会并发积压请求；拍照仍由 `SaveSourceScreenshot` 保存原始来源 PNG，录像仍由 OBS 输出。取消原有 180 ms 等待后，本机单页面三次实测为 44.2～46.2 FPS，预览为 960×720，页面显示请求至呈现约 18～20 ms。网页截图刷新率不等于手机独立帧率；若 DroidCam 来源实际约 14 FPS，更高的网页刷新率会包含重复画面。手机传输延迟需要另计。
- 运行日志位于网页“采集控制”面板中，记录最近 50 条连接、拍照、自动拍照、录像和错误事件。若启动命令提示“控制台已在运行”后立即返回，表示另一个进程已经占用 8765；本次命令没有启动新服务，因此当前终端不会打印该服务的请求日志。
- 网页关闭或刷新会请求断开当前来源；再次打开页面后可重新连接。
- 点击“断开 OBS 控制”停止本项目的录像和定时拍照并关闭连接；正常关闭后端也执行清理。不会退出用户自行启动的 OBS，也不会删除创建过的手机场景。
- 断线后每隔约 3 秒尝试重新认证；自动拍照停止，不重放录像/截图指令。若断线时本项目录像可能仍在继续，重连后停止该录像并要求检查断线期间内容。通信中断期间无法保证 OBS 停止，页面将录像状态标为未知。
- OBS 密码错误时，底层客户端接收到关闭帧后的普通 `close()` 可能提前返回；本项目补充了底层套接字 `shutdown()`，真实握手测试确认错误密码后连接被释放。
- `StopRecord` 返回文件路径时，编码器和封装器可能还在完成输出。后端会等待 `GetRecordStatus.outputActive` 变为 false，再返回停止成功；最多等待 15 秒，超时明确报错，不提前声称文件已经完成。
